# 🔍 Анализ проблемы авторизации в OpenCode Party Mode

**Дата анализа**: 2026-01-06  
**Проблема**: Ошибка "Unauthorized" (401) при параллельном запуске агентов в party mode

## 📊 Обнаруженная проблема

### Ошибка в логах

```
ERROR 2026-01-06T16:41:08 service=llm providerID=google modelID=gemini-3-flash-preview 
error={"statusCode":401,"responseHeaders":{"access-control-allow-origin":"*"}}
```

**Ключевые детали**:
- **Провайдер**: Google (Gemini)
- **Модель**: `gemini-3-flash-preview` (⚠️ не настроена в конфигурации)
- **URL**: `http://127.0.0.1:8045/v1beta/models/gemini-3-flash-preview:streamGenerateContent?alt=sse`
- **Статус**: 401 Unauthorized
- **Контекст**: Party mode с параллельными агентами

## 🔍 Анализ причин

### 1. Неправильное имя модели

**Проблема**: Используется `gemini-3-flash-preview` вместо `gemini-3-flash`

**Текущая конфигурация** (`opencode.json`):
```json
{
  "provider": {
    "google": {
      "models": {
        "gemini-3-pro-high": {...},
        "gemini-3-flash": {...}  // ✅ Правильное имя
      }
    }
  }
}
```

**Причина**: 
- OpenCode или oh-my-opencode пытается использовать модель `gemini-3-flash-preview`
- Эта модель не определена в конфигурации
- Proxy возвращает 401, так как модель не распознана или токен недействителен

### 2. Race condition при параллельных запросах

**Проблема**: При параллельном запуске нескольких агентов в party mode:

1. **Несколько агентов одновременно** запрашивают доступ к API
2. **Один токен** используется для всех запросов
3. **Токен может истечь** между запросами
4. **Обновление токена** может не успевать синхронизироваться между параллельными запросами

**Из кода** (`src/auth/antigravity/fetch.ts`):
```typescript
// Проверка истечения токена
if (isTokenExpired(cachedTokens)) {
  debugLog("Token expired, refreshing...")
  // Обновление токена
  const newTokens = await refreshAccessToken(...)
  // ...
}

// Если несколько запросов одновременно проверяют токен:
// - Запрос 1: токен истек → начинает обновление
// - Запрос 2: токен истек → тоже начинает обновление
// - Race condition: оба пытаются обновить токен одновременно
```

### 3. Проблема с Antigravity Proxy

**Возможные причины**:
- Proxy не успевает обрабатывать параллельные запросы
- Токен API proxy (`sk-d0f78503acb64c6fb3b56a3569d43935`) может иметь ограничения по rate limit
- Proxy может требовать уникальные токены для каждого запроса

## 🛠️ Решения

### Решение 1: Исправить имя модели

**Проблема**: Используется `gemini-3-flash-preview` вместо `gemini-3-flash`

**Действия**:
1. Проверить, где определяется модель для агентов
2. Убедиться, что все агенты используют правильные имена моделей из конфигурации
3. Проверить конфигурацию `oh-my-opencode.json` на наличие ссылок на `gemini-3-flash-preview`

### Решение 2: Добавить синхронизацию обновления токенов

**Проблема**: Race condition при обновлении токенов

**Рекомендации**:
1. Добавить мьютекс/блокировку для обновления токенов
2. Кэшировать обновленный токен для всех параллельных запросов
3. Использовать очередь для обновления токенов

**Из кода** (`src/auth/antigravity/fetch.ts:387-431`):
```typescript
// Текущая реализация не имеет синхронизации
if (isTokenExpired(cachedTokens)) {
  // Множественные запросы могут попасть сюда одновременно
  const newTokens = await refreshAccessToken(...)
}
```

### Решение 3: Проверить конфигурацию Antigravity Proxy

**Проблема**: Proxy может не поддерживать параллельные запросы с одним токеном

**Действия**:
1. Проверить логи proxy сервера
2. Убедиться, что proxy поддерживает параллельные запросы
3. Проверить rate limits proxy

### Решение 4: Использовать правильные модели в конфигурации агентов

**Проверка** `oh-my-opencode.json`:
```json
{
  "agents": {
    "document-writer": {
      "model": "google/gemini-3-flash"  // ✅ Правильно
    },
    "multimodal-looker": {
      "model": "google/gemini-3-flash"  // ✅ Правильно
    }
  }
}
```

**Проблема**: Где-то используется `gemini-3-flash-preview` вместо `gemini-3-flash`
